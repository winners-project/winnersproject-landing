Turma fundadora em preparação

Do git tag ao hardware, sem deploy manual.

Uma imersão prática para desenvolver uma esteira de CI/CD que compila, empacota e entrega aplicações C/C++ para Embedded Linux em ARMv7 e ARM64.

Quero entrar na lista de espera → Ver o que será construído

Sem promessa de milagre. Um template técnico, adaptável ao seu projeto.

$ git push origin v1.0.0

✓ build arm64

✓ publish artifacts

O problema

Uma release não deveria depender de memória, comandos soltos e cópia manual de arquivos.

01

Você compila em uma máquina e descobre tarde que o binário não funciona no dispositivo.

02

Cada hardware exige uma sequência diferente de binários, dependências e permissões.

03

Uma tag de versão não resulta automaticamente em um artefato reproduzível e instalável.

O resultado

Uma base de entrega para seu software embarcado.

  • ✓ Pipeline acionada por tag de versão, como v1.2.0
  • ✓ Builds reproduzíveis em Docker para ARMv7 e ARM64
  • ✓ Artefatos versionados com binários, bibliotecas e scripts
  • ✓ GitHub Actions para build, testes, empacotamento e release
  • ✓ Instalador idempotente e adaptável ao dispositivo-alvo
  • ✓ Checklist para levar o template ao seu projeto

A imersão

Quatro encontros ao vivo. Um fluxo completo.

Módulo 01

Arquitetura de release

Tags, versões, artefatos, rastreabilidade e limites de uma esteira de CI/CD para user-space em Embedded Linux.

Módulo 02

Build reproduzível

Docker, CMake, dependências e cross-compilation para reduzir diferenças entre máquinas e alvos.

Módulo 03

Pipeline no GitHub Actions

Jobs por arquitetura, gatilho por tag, cache, artefatos e publicação de uma release.

Módulo 04

Pacote e instalação

Layout de release, detecção de plataforma, instalação, permissões e smoke test no hardware.

Esta imersão é para você se

  • Desenvolve aplicações C/C++ para Linux embarcado
  • Entrega software em Raspberry Pi, Jetson, gateways, SBCs ou robôs ARM
  • Já usa Git, GitHub e terminal no dia a dia
  • Quer sair de SCP, pendrive e procedimentos manuais de release

Não é o foco desta turma

  • Firmware bare-metal ou FreeRTOS sem Linux
  • Yocto, Buildroot ou construção de imagem de sistema operacional
  • OTA de frota, particionamento A/B ou certificação regulatória
  • Suporte garantido a todo BSP, distro ou hardware existente

Perguntas frequentes

Preciso ter Raspberry Pi ou Jetson?

Não para acompanhar a arquitetura e o pipeline. Para executar o fluxo completo no seu contexto, um dispositivo Linux ARM próprio é recomendado. O exemplo principal será orientado a Raspberry Pi ARM64; outros alvos exigem adaptação.

Isso é um curso de Docker ou GitHub Actions?

Não isoladamente. Docker e GitHub Actions são ferramentas dentro de um objetivo maior: uma entrega reproduzível de aplicação C/C++ para hardware Linux ARM.

O evento cobre OTA e atualização de frotas?

Não nesta primeira turma. O foco é build, empacotamento, release e instalação local/adaptável. OTA, rollback atômico e fleet management são temas avançados e separados.
